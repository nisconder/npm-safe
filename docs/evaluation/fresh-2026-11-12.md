# Fresh packages, unchanged scanner — 2026-11-12

The first run on this new cohort found **0 of 8 malicious samples** and raised
High/Critical alerts on **2 of 12 normal controls**. All 20 deep scans reported
`complete`. The scanner and rule configuration were not changed in this round.

The previous [8/8 repair result](repairs-2026-11-12.md) is a regression result
on observed inputs. It did not establish generalization to new packages. This
new result exposes substantial remaining detection gaps and two concrete false
positives; it is also a selected small cohort, not an ecosystem accuracy estimate.

## Frozen protocol and provenance

- Scanner frozen before selection/acquisition at `2026-11-12T09:15:33.752Z`.
  Source fingerprint remains

  All 80 frozen core-source/evaluation files were verified unchanged before

- Eight malicious and twelve provisional benign versions were selected from
  public research labels, official project identity and archive/Registry
  metadata before viewing source or scanner outcomes. There was no overlap
  in package name or exact version with 235 recorded historical coordinates.
  Shared transitive code is still possible; this does not prove complete
  family independence or absence of exposure outside available project records.
- Undici and Sentry were considered, then replaced with Fastify and
  OpenTelemetry before artifact download because of earlier project exposure.
  No package was replaced based on scan output. All 20 selections were acquired
  and prepared successfully, with zero acquisition exclusions.
- Malicious ZIPs came from the DataDog archive at fixed commit
  `72c723be547033c558244520524b117c8d71663b`, with Git blob and SHA-256 checks.
  Source files were repacked into TAR/gzip in memory and every rebuilt member
  was compared with the original bytes. Original npm tarball SRI is not claimed
  for these repacks. Normal controls retain official npm tarballs and verified SRI.
- Existing source evaluation harness, default rules, no cache, no plugins or
  LLM, Windows x64 / Node 24.22.1. Metadata input is archived package.json and
  README, not a live Registry reputation lookup. Package code was never
  installed, imported or executed; no payload endpoints were contacted.

The two false positives already occur in metadata mode:

- `@electron/get`: `typosquatting` removes the `@electron` scope and compares
  `get` to `jest`, reporting edit distance 2. The package is the
  [official Electron artifact downloader](https://github.com/electron/get).
  The additional Medium finding in deep mode is accurate capability evidence:
  `dist/cjs/utils.js:55` runs `uname -m` to identify the host architecture.
- `dotenv`: `secret-exposure` recognizes a private-key BEGIN marker in the
  README's multiline-variable examples (lines 104–119), even though the body
  is explicitly abbreviated with `...`. These are documentation placeholders,
  not complete exposed credentials. The frozen regex at `static-rules.ts:198`
  checks the marker, and the rule at line 475 emits Critical. The source is the
  [official dotenv project](https://github.com/motdotla/dotenv).

## Label evidence and operational limits

Primary evidence:
[node-ipc](https://securitylabs.datadoghq.com/articles/node-ipc-npm-malware-analysis/),
[nodelogic / MUT-8694](https://securitylabs.datadoghq.com/articles/mut-8964-an-npm-and-pypi-malicious-campaign-targeting-windows-users/),
[Rspack maintainer notice](https://github.com/web-infra-dev/rspack/issues/8767),
[XMLRPC investigation](https://zero.checkmarx.com/dozens-of-machines-infected-year-long-npm-supply-chain-attack-combines-crypto-mining-and-data-0c674ac4dcbd),
[Ethereum-tool RAT](https://socket.dev/blog/quasar-rat-disguised-as-an-npm-package),
[slf4j impersonation campaign](https://socket.dev/blog/npm-targeted-by-malware-campaign-mimicking-familiar-library-names),
[Excel-converter destructive backdoor](https://socket.dev/blog/npm-package-wipes-codebases-with-remote-trigger),
[crypto-encrypt-ts](https://www.sonatype.com/blog/revived-cryptojs-library-is-a-crypto-stealer-in-disguise).
For the Ethereum and slf4j samples, the article confirms the package/campaign
and the curated archive supplies the exact version; all archived manifests
were checked against the frozen selected coordinates.

Two source-quality observations must remain attached to the result:

- The original `slf4j-api-js` postinstall string contains an actual newline
  inside a quoted path, and its manifest entry path does not match the archived
  source layout. Its automatic trigger may be broken. The data-collection/TCP
  source is present, but successful automatic infection is not established.
- `xlsx-to-json-lh` includes the remote deletion code but does not directly
  declare the `socket.io-client` dependency it uses. Runtime availability
  depends on its environment and was not tested.

The cohort measures detection of archived malicious content/intent, not
successful infection. Neither sample was silently dropped or replaced.
Excluding both operationally limited samples still leaves **0/6 malicious
alerts**, so they do not account for the poor detection result.

`complete` is not a claim of complete semantic analysis. The archive and text
budgets were not exhausted, but unsupported network APIs, object/helper flows,
large opaque literal values and other obfuscation shapes remain invisible to
these narrow heuristics. No rule was repaired after observing these outcomes.
Once these cases are used to tune rules, they become regression data rather
than a new independent test set.

## Reproducible records

[Machine-readable results](fresh-2026-11-12.results.json) retain the exact
dataset, source/artifact hashes, all 40 metadata/deep rows, provenance,
acquisition/preparation status and independent read-only triage. Source snippets
are omitted from portable finding rows; complete package source is not committed.
Raw archives, immutable selection/freezing records and original results remain
under `.npm-safe/fresh-evaluation-20261112/` locally.

The first run used `run.mjs` in that directory, which verifies the frozen code
and inputs before and after invoking the existing evaluator. A reproduction
with those local artifacts can use a new output path:

```powershell
node scripts/evaluate-scanner.mjs .npm-safe/fresh-evaluation-20261112/dataset.json --output .npm-safe/fresh-evaluation-20261112/reproduction.json --split test
```

No new scanner implementation tests or build were needed: production code is
byte-identical to the previously tested source. This run validates corpus
behavior and input/source integrity, not additional implementation changes.
