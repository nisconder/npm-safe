# 源码模型原型 v2：取码改进与新样本对照

本轮改进了源码优先级、预算利用率和一次补充取码机制，生产扫描规则保持冻结。新一批 4 个恶意包、8 个正常对照全部完成评测：规则检出 1 个恶意、误报 2 个正常；源码模型检出 2 个恶意、另 2 个不确定，8 个正常对照无模型误报。不能把不确定计为检出，也不能把这小批样本的零误报推广到所有 npm 包。

旧样本开发回归的模型检出从 **2/5 提升到 5/5**，11 个正常包仍无模型误报。这个回归提升表明之前定位的取码缺陷得到改善，不能作为未见样本的准确率。

## 实现变化

1. **运行源码与关键结构优先。** 类型声明不再挤占运行入口的采样名额；动态执行、编码载荷等结构优先于普通网络/文件能力的累计分。这些只是选材信号，不直接判恶意，也没有包名或固定载荷特例。
2. **用足已分配预算。** 先回收短文件用不完的份额，再分配给长文件；片段重叠合并后，用尚未覆盖的字符回填。初始预算仍是 40,000 UTF-16 字符、16 文件、每源码文件 8,000 字符，manifest 2,000、README 1,200。
3. **允许模型请求一次补充。** 初始包提供最多 64 个可补取路径及长度。模型可以一次请求最多 4 个原始范围，总计额外 40,000 字符、每文件累计至多 24,000 字符。模型不能自行读归档或其他文件；协调器只从已核验哈希的原始归档返回指定片段。
4. **补充过程可审计。** 请求、单次机会标记、回执和补充包均保留。失败也消耗机会并弃权，待处理请求不能算安全；比较时从原始归档重建补充内容，校验原文与偏移。路径读写受目录边界检查，但不是 OS 权限沙箱。
5. **修复准备脚本的目录假设。** 官方 tarball 的浅层唯一 `package.json` 不再必须位于 `package/` 下。旧 ssh2 官方归档已成功准备并完成离线深扫，SRI 验证成功，safe / 81。它是已见的操作回归，未计入新样本或模型成绩。

### 命中、误报和不确定的原因

`@teale.io/eslint-config` 是模型新增的明确命中。安装入口包含完整的持久化链：解码嵌入的 Python 文本、写入用户目录、创建并启用服务；解码后的程序定期查询外部地址，下载对方指定的可执行文件并启动。这与 ESLint 配置用途无关。模型没有宣称远端二进制内容、实际启动或窃密已经得到验证。标签依据为 [Socket 的 CanisterWorm 研究](https://www.socket.dev/blog/canisterworm-npm-publisher-compromise-deploys-backdoor-across-29-packages)。

`@nx/devkit` 被双方命中。模型请求补齐完整 `telemetry.js` 后，连接了非 Windows 分支中的安装触发、调用本机 AI CLI 搜索秘密、读取文件/环境/令牌、向公开 GitHub 仓库提交收集结果的链，并发现修改 shell 启动文件的破坏性命令。源码中的恶意提示词按数据分析，没有作为本次审查指令执行。实际成功仍依赖权限、工具、令牌和网络条件。标签依据为 [Nx 维护者的 s1ngularity 复盘](https://nx.dev/blog/s1ngularity-postmortem)。

`deezcord.js` 在补充后仍缺少一部分执行连接与远端返回命令，保留不确定；`windows-confirm` 本地源码展示下载后启动可执行文件，但实际载荷缺失，模型没有仅凭下载执行能力判恶意。两者的预选恶意标签分别来自 [Socket 的多阶段凭据窃取研究](https://socket.dev/blog/10-npm-typosquatted-packages-deploy-credential-harvester)和 [Skuld 研究](https://www.socket.dev/blog/skuld-infostealer-returns-to-npm)。这两个已知恶意样本仍未被模型明确检出，是本轮的实际限制。

规则对 `jose` 和 `vm2` 的误报都来自编辑距离：分别把它们与 `jest`、`vue` 的名称相似性提升为 High。源码模型没有沿用这个名字信号。`node-forge` 的补充材料则澄清了 Worker 用于并发估计和素数搜索，说明补充取码也可用于确认合法行为，而不是只增加报警。

新样本共发生 4 次补充请求，全部成功，额外传输了 **59,801** 字符，其中新增覆盖 **54,609** 字符，其余为与初始证据重叠的上下文。这比 v1 允许更多证据，不能把全部收益都归因于初始排序改进。

初始证据共 323,686 字符。12 个归档检查均 complete，但初始源码视图 11 个 partial、1 个 complete；唯一 complete 是 `windows-confirm`，它仍因远端可执行文件缺失而不确定。读完本地源码不等于掌握远端后续载荷。

## 冻结与验证边界

v2 于 **2026-11-12 12:08:56 UTC** 冻结，随后才下载新样本。规则源码指纹仍是 `0e0d3b94b25cb9478af18c9524928dc2ed631d7e336f62ca5c1a8ecbe06f067f`；v2 原型指纹为 `6f44697899f8effdb22bc1a029e728b144d6d8c5421d49a722777c80c2d4ee2b`。研究档案固定在 DataDog commit `72c723be547033c558244520524b117c8d71663b`。

每包使用无历史对话的新审查实例；只提供冻结提示词和该包证据，补充由同一实例继续阅读。没有提供标签、研究报告、规则结果或另一包的答案。原始源码仍可能显露包名，无法排除预训练记忆；任务指令隔离也不等于 OS 沙箱。没有安装、运行样本或联系载荷端点。

模型为当前会话继承模型，没有调用独立付费 API。准确模型标识、温度、token 用量和金额不可见；因此这些结果是本次会话实验，不是可确定性复现的 API 基准。每包只保存一次最终判断，不根据标签纠正答案。原始源码引用校验只验证位置和文字，不自动证明推理正确。

原型及评测工具测试 **61 通过、0 失败、1 跳过**。唯一跳过项需要目录链接权限，当前 Windows 沙箱不允许；普通目录越界、一次机会消费、原档案重建、伪造证据拒绝、失败弃权、CRLF/UTF-16 行号和预算回填均已通过测试。

28 份最终评审与 8 次原始补充请求均保留；没有看到标签后修正评审。新样本的两条阳性及两条规则误报经过独立只读语义复核，支持上述收窄后的结论；真实源码引用不自动证明运行成功。
