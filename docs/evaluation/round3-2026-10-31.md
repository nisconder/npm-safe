# 第三轮：正常行为误报修复与深扫性能

> 本页数值与耗时保留为合并前 core 1.1.1 的历史快照。当前 core 1.1.2 的等级策略与同样本复核见[上游整合核对](integration-2026-10-31.md)；历史结果和性能表未重写。

在与第二轮完全相同的 16 个版本上，三个已知恶意版本继续被深度扫描命中。十个正常挑战版本中，完整深扫的产品等级误报从 **3/9 降为 0/9**，高危告警误报从 **5/9 降为 1/9**；WalletConnect 仍部分完成，未计作正常阴性。本轮串行测量的正常挑战深扫 p50 从 **32.183 ms 降为 22.500 ms**、p95 从 **169.281 ms 降为 67.218 ms**，元数据扫描 p95 则从 **1.512 ms 增为 5.601 ms**。

这是已知回归集和已观察挑战集上的工程改进。样本、规则范围和测量限制均保留，不能据此声称总体零误报、独立样本召回率不变或所有扫描路径都加速。

## 修改及覆盖代价

- `base64-shell` 要求局部命令中可识别的字面量解码→解释器输入，或明确的 PowerShell 编码命令。长 URL、徽章、普通数据解码和其他位置的 shell 词不再组合成高危证据。保留围栏/行内安装命令、管道及受限命令替换正例；`printf -v` 不输出数据、`sh -s -c` 不读取管道脚本等边界有回归测试。
- `binary-links` 解析 HTTP(S) URL 的 pathname 后缀，域名、查询参数和片段不能提供 `.sh`/`.exe` 后缀；真实下载路径仍支持大小写、查询参数和编码路径。
- `content-network-exec` 从“同文件存在网络及进程能力”收窄为受限的本地连通关系：已识别的 child-process 绑定收到 fetch 响应文本，作为命令或 shell `-c` 输入。合法安装器的独立下载与工具启动不再仅凭共现扣 high 分；普通进程能力和安装钩子的 medium 发现继续保留。
- 词法分析用字符分类和无转义字符串快速路径减少逐字符正则及分配开销，保留原始位置、令牌内容和截断标志。

没有包名、版本、域名或文件哈希白名单，也没有改评分权重、等级阈值。网络规则只理解列出的本地赋值和调用形状；自定义 HTTP 回调、Promise 链、下载落盘后执行、任意变量/跨函数传播仍可能漏报。README 检查也不是完整 shell 解释器。**范围收窄存在漏报风险**，旧恶意回归集没有覆盖这些未知形状，不能用本轮 3/3 证明全面召回率保持不变。
