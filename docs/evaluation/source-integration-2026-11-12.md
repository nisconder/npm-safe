# 源码 LLM 可选接入：生产路径与会话复测

源码分析原型已经移植到 npm-safe 的生产包，作为**独立开关、默认关闭**的源码复核。
配置并启用模型、开启 `llm enable-source` 后，`check --deep` 才运行这条路径。
静态扫描与模型复核使用同一次下载的归档，该次深扫不再额外调用元数据模型。
当前没有训练本地模型；源码会发送给用户配置的模型服务。

本次区分两种验证：28 个旧样本的冻结响应回放，以及 8 个已见包的当前会话新判断。
前者检查移植和接入是否保留证据与结果，后者观察一次新的模型判断；二者都不是
未见包的独立准确率评测，也不能合并为 36 个独立样本。

## 接入行为与边界

源码选择保留原型的入口优先、关键结构排序和预算回填：初始最多 40,000 个 UTF-16
字符、16 个文件、每源码文件 8,000 字符。模型可请求一次补充，最多 4 个范围、
额外 40,000 字符、每文件累计 24,000 字符。一个包最多两次模型请求。
所有读取在内存中完成，不安装、导入或执行被检查的包，不联系包内载荷地址。

模型结果作为独立 `sourceReview` 报告保留。引用必须精确匹配已提供源码位置，
伪造引用、无效 JSON、预算超限、请求失败和缺失源码均不能成为干净阴性。
模型 `benign` 只表示给定视图未发现恶意，不能消除静态告警或提高静态分数。
请求的源码复核失败或返回 `unknown` 时，原本为 `safe` 的联合结果变为 `unknown`；
已有静态 `suspicious` / `dangerous` 结果仍保留。源码复核结果不缓存。

本机没有配置可调用的模型密钥。本次未发送真实付费 API 请求：OpenAI 兼容、Gemini
与 Anthropic 的请求构造通过离线测试；真实引擎与 OpenAI 兼容 provider 的数据流
通过拦截 `fetch`、返回冻结或新会话判断进行验证。任何未预期网络请求都被拒绝，
没有真实网络回退。真实服务的可用性、模型输出稳定性与账单仍未实测。

## 28 个旧样本：冻结响应回放

这 28 例来自 v2 的 16 个开发回归包与当时的 12 个新包，共 9 个恶意版本、19 个正常
对照版本，现在全部是已见样本。准备时重新核验原数据集、manifest、README、归档、
初始证据、原始请求、补充及最终判断的哈希，不改旧判断。

实际执行 `NpmSafeEngine.checkPackage(..., { deep: true })`，调用生产 provider，
只有传出的初始和补充源码与原冻结材料完全一致，才返回旧模型响应。仅重新绑定
由归档哈希派生的 case ID，源码、偏移和引用保持不变。所有 28 例回放成功，
28 份初始证据和 8 份补充精确匹配。

| 判定来源 | 恶意检出 TP | 恶意阴性 FN | 恶意不确定 | 正常误报 FP | 正常阴性 TN |
| --- | ---: | ---: | ---: | ---: | ---: |
| 当前静态规则 | 1 | 8 | 0 | 2 | 17 |
| 冻结模型判断 | 7 | 0 | 2 | 0 | 19 |
| 联合策略 | 7 | 0 | 2 | 2 | 17 |

模型的实际检出是 7/9，另外 2 个不确定不能计作检出。正常对照的模型零误报只描述
这组已知样本；联合策略仍保留 2 个静态误报。以上数字重现旧判断，不是新模型成绩。

每个包都另跑默认关闭配置作为对照：模型请求为 0，静态分数、等级和发现项与开启
源码复核时相同。开启后每包仅下载一次归档，28 包共构造 36 次模型请求。初始源码
828,292 字符，补充 174,754 字符，其中新增覆盖 159,832 字符。第二轮会重新发送
初始包，因此产品请求累计传送源码 1,242,366 字符，含系统提示词和 JSON 的 prompt
累计 2,016,108 字符。这些是本地构造请求的 UTF-16 字符计量，不是 API token 用量
或真实会话模型的账单。

## 8 个已见包：当前会话模型重新审查

从上述样本中固定选择 4 个恶意版本和 4 个正常对照。每包另开无历史上下文的审查
实例，只提供生产路径实际生成的系统提示词与该包源码；没有提供标签、旧判断、
规则结果或其他包的答案。源码本身可能显露包名，预训练记忆不能排除；对话隔离
也不是 OS 权限沙箱。判断使用当前会话继承模型，准确模型标识、温度、token 与费用
不可见，未通过独立模型 API 进行新推理。

模型产生新的最终 JSON 后，将它作为本地响应重新经过生产 engine、provider 和
引用验证。3 次补充从原始哈希验证归档重建，8 份判断及全部 38 条引用有效，
没有修正模型结论，未排除任何选定样本，接入验证失败数为 0。

| 判定来源 | 恶意检出 TP | 恶意阴性 FN | 恶意不确定 | 正常误报 FP | 正常阴性 TN |
| --- | ---: | ---: | ---: | ---: | ---: |
| 当前静态规则 | 1 | 3 | 0 | 2 | 2 |
| 本次会话模型 | 2 | 0 | 2 | 0 | 4 |
| 联合策略 | 2 | 0 | 2 | 2 | 2 |

本次模型检出 **2/4** 个恶意版本，另外 **2/4 为不确定**；不能用“已作出二元判断
的恶意样本全部命中”替代实际检出率。四个正常对照没有新增模型误报，但联合策略
仍有两个静态误报。该结果与这八包此前的 v2 判定一致，是已见包的新会话复测，
不能据此声称新样本泛化能力提高。

| 准确包版本 | 静态等级 | 新模型判断 | 产品联合等级 | 补充字符 |
| --- | --- | --- | --- | ---: |
| `@nx/devkit@21.5.0` | suspicious | malicious | dangerous | 6,855 |
| `@teale.io/eslint-config@1.8.10` | safe | malicious | suspicious | 0 |
| `deezcord.js@1.0.0` | safe | unknown | unknown | 24,000 |
| `windows-confirm@1.0.0` | safe | unknown | unknown | 0 |
| `jose@6.0.11` | suspicious | benign | suspicious | 0 |
| `vm2@3.9.19` | suspicious | benign | suspicious | 0 |
| `puppeteer@24.8.2` | safe | benign | safe | 0 |
| `ky@1.7.5` | safe | benign | safe | 6,508 |

`@teale.io/eslint-config` 的隐蔽安装链解码 Python 程序、创建用户持久服务，再按
远端响应下载并启动可执行文件，与所声明的 ESLint 配置用途不符。`@nx/devkit`
补齐安装脚本后，能连接凭据/文件收集、尝试发布到公开仓库及修改 shell 启动文件
的破坏性动作。两例均是源码所支持的行为，不证明服务实际启动、令牌可用、上传
成功或机器实际关机；外部工具、系统权限及后续载荷仍在证据边界之外。

两个未检出的恶意样本仍有明确限制：

- `deezcord.js` 补充后，`package/app.js` 的 UTF-16 范围 `[26665, 32847)` 仍未
  提供，部分解码初始化、辅助函数和字符串表映射不能完整验证。已见安装触发的
  CAPTCHA 流程从远端 JSON 取得平台命令，但返回的实际命令及其作用不在证据中。
  出现权限/密码提示字符串也不能单独证明密码收集与传输，因此保留 `unknown`。
- `windows-confirm` 的两个本地文件全部可见，但安装时下载并运行的远端可执行
  文件不在归档里。该实现也符合其声明的更新器用途，缺少载荷内容无法仅凭下载
  执行链确立恶意行为，因此保留 `unknown`，不把本地覆盖完整等同于安全。

`jose` 与 `vm2` 的静态误报仍来自包名编辑距离，模型没有把正常密码学/沙箱能力
判为恶意；`jose` 的一条 Low 说明不计作模型报警。`ky` 补充厘清调用者驱动的 HTTP
请求路径，`puppeteer` 的下载/进程能力也未被模型单独判恶意。联合策略保留静态
告警，因此本轮没有新增误报，也没有自动消除原有误报。

这 8 例的归档检查全部完整，初始源码视图 7 个 partial、1 个 complete。初始共
196,110 字符，3 次补充共 37,363 字符，其中新增覆盖 33,253 字符。产品验证共构造
11 次模型请求，包含第二轮重传的源码字符总量为 302,592，prompt 字符总量为
508,228。这些统计描述生产传输格式；审查实例实际消耗的模型 token、耗时和金额
未测得，不能由字符数直接推算。

## 实现验证

Windows x64 / Node 24.22.1 下，类型检查和构建通过；核心测试 728 通过、2 跳过、
0 失败；评测工具 18 项通过。打包预览确认 36 个源码复核相关文件包含在产物中。
测试覆盖默认关闭、显式开启、三个 provider、一次补充、超限和错误响应、引用伪造、
取消、同一归档复用、旧缓存隔离、静态告警保留以及 CLI 输出。

这些实现测试验证覆盖到的行为，不能证明恶意检测准确率。完整归档解析也不意味着
完整源码覆盖、控制流追踪或运行时安全。正常对照标签不是无漏洞保证，历史包版本
仅供检测研究，不构成安装推荐。

## 可复核记录

两份接入结果使用相同生产/评测源码指纹：
`b5d8168c5df854e1134a587532fc5a2d6988a0e56ae27d4d1a56a054ff92f3aa`。
JSON 记录每包静态结果、独立模型判断、联合等级、原档案/判断哈希、覆盖与字符
计量；公共记录不复制原始源码或完整凭据。新会话的原始判断和补充记录保存在本地
`.npm-safe/integrated-source-new-review-20261112/`，旧 v2 记录未被改写。

已有本地原档案时，可用以下命令复现冻结响应接入验证：

```powershell
node scripts/evaluate-integrated-source.mjs replay .npm-safe/llm-source-v2-20261112/run .npm-safe/llm-source-v2-20261112/regression/run --output .npm-safe/new-integration-replay.json
```

输出路径必须尚不存在。新会话验证调用同模块的 `evaluateIntegratedSource`，传入
相同两个原始 run 路径和 `reviewInbox`；它读取独立保存的新判断，而不是改写旧响应。
这能复现产品对已保存响应的处理，不能确定性复现模型的新推理。
