# 第二轮扫描修复与评测：2026-10-31

两个已知漏报已补上：深度扫描对原有三个恶意版本的命中从 **1/3 变为 3/3**，三个原有对照保持阴性。新增十版本正常行为挑战集中，完整深扫的高危告警误报从 **6/9 降至 5/9**，产品等级误报从 **5/9 降至 3/9**；另一个版本始终部分完成，没有当成正常阴性。这是工程回归与挑战集结果，不能解释为生态总体检测率或独立盲测成绩。

## 改动及适用范围

新增 `content-concealed-native-exec`（high）：只静态还原受限的字符串字面量拼接/转义，结合隐藏的 child-process 调用、固定原生加载器和 DLL 入口参数。新增 `content-browser-interception`（critical）：要求可执行代码中的全局 fetch 替换、Response 构造、XMLHttpRequest 方法替换以及两类加密货币地址匹配表达式同时出现。单纯使用钱包 API、网络 API 或进程 API 不满足这两个新规则。

JavaScript 动态执行检查改为大小写敏感的词法调用证据，注释、字符串、正则里的示例不再当成调用。没有调整分数阈值，没有包名、版本、文件哈希白名单，也没有执行包代码。此实现不是 AST 或完整数据流分析；字符串常量折叠最多 4,096 字符，不计算变量值或模板表达式。

## 输入与判定

原[六版本试评](pilot-2026-10-31.md)已被分析并用于修复，本轮统一视为**已知回归集**；JSON 中保留的历史 dev/test 标签不再代表留出评测。三个恶意输入仍是带完整派生记录的源码重打包，不能验证原始发布归档结构或 SRI。

新增[十版本冻结清单](round2-2026-10-31.controls.dataset.json)覆盖安装器、编译器、进程工具、钱包连接、浏览器遥测、HTTP 客户端与动态代码工具。先固定选样和输入，再运行扫描；十个原始 Registry tarball 都核验了发布 SRI/SHA1，没有按扫描结果替换或删除样本。正常标签依据项目归属、用途及静态核对，仍是暂定标签。该集合没有恶意正例，不能计算召回率；其 `split: test` 是运行器字段，经过本轮观察后也不是独立盲测集。

沿用两套判定：高危告警为至少一个 high/critical 行为发现；产品阳性为 `suspicious` 或 `dangerous`。产品 `safe` 为阴性，`unknown` 弃权；partial/failed 对两套判定均弃权。能力告警可能描述真实的合法功能，下面的 FP 指它作为**恶意包分类信号**时与暂定正常标签不符。

```powershell
.\packages\core\node_modules\.bin\tsc.cmd -p .\packages\core\tsconfig.json
node scripts/evaluate-scanner.mjs .\local-corpus\dataset.json --output .\results-new.json
```

构建核对本地 dist 产物，离线运行器仍直接加载当前 TypeScript 源码，并记录文件哈希；它不使用生产缓存。手工核对当前本地 CLI 时，给 `check` 同时传 `--deep --refresh`，避免复用旧规则生成的缓存报告。当前源码与本地构建均为 14 条内容规则；实现见[词法分析](../../packages/core/src/scanner/source-tokens.ts)、[进程信号](../../packages/core/src/scanner/content-process-signals.ts)、[浏览器信号](../../packages/core/src/scanner/browser-signals.ts)与[动态执行检查](../../packages/core/src/scanner/content-dynamic-signals.ts)。

样本原件、冻结旧扫描器、获取/派生脚本与基线适配器保留在本地证据目录；仓库没有分发恶意包，也没有声称一条命令即可重建语料。重新获取不能覆盖冻结清单。旧代码的原始字节指纹同样受换行格式影响，应以保存的源码哈希核对。本轮交付为工作区改动及本地构建，尚未发布新版本。
